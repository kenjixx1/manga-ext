Comix K Stage 3 Options

The hidden browser view inside Tachimanga can never reach Comix by itself on iPhone. To fix browse and chapters, the site must be reached only through the app's own requests.

What we proved with versions 1.6.3 to 1.6.8

Why it breaks

  • The manga list and the chapter pages come from Comix's data API. Each call needs a one-time token.
  • Only the site's own code can make that token. It lives in a 215 KB file written in scrambled form on purpose, so Comix K cannot rebuild it.
  • So the site's code must run in a browser view, but its network requests must go through the app. The app is the only path that passes.
The choice

3 ways forward

recommended

A · Route the hidden view through the app

The site's code still runs in the hidden view. Every file and data request it makes is handed to the app, which fetches it with the Safari name tag and the pass, then hands the answer back.

Fixes
Browse, search, chapter list, chapter pages
Risk
Needs 3 iPhone abilities we have not tested yet (see probe below)
Size
Large. A new piece of about 200 lines. Planned and reviewed like Stage 2.
do anyway, costs 10 minutes

B · Report the bug to Tachimanga

Their hidden browser view ignores the name tag an extension sets. If they fix it, keiyoushi's normal Comix code works on iPhone with Mobile Safari, and no big change is needed.

Fixes
Everything, for every Comix user on iPhone
Risk
We wait. No control over when, or if, they fix it.
Size
One clear bug report. I write it, you send it.
not recommended

C · Rebuild the token in Comix K

Decode the scrambled token code and copy it into the extension, so Comix K calls the data API directly with no browser view.

Fixes
Everything, while it lasts
Risk
The site changes its code often. Comix changed 5 times in 5 days. Each change breaks this.
Size
Very large and fragile
Before building A

One small test build first (1.7.0)

Option A depends on 3 things the iPhone hidden view may or may not support. One test build checks all 3 at once, and you send me one Diagnostics text. If any one fails, A is not possible, and we keep B.

1 · app → page messagesCan the app send an answer back into the page? A needs this to return each fetched file and data reply.
2 · code from the appWill the hidden view run the site's code when the app supplies it, instead of loading it from Comix?
3 · the token, offlineDoes the site's code still make its token when every network request is handed to the app?
Evidence: Diagnostics from Comix K 1.6.3 to 1.6.8 on iPhone, plus tests on your Mac against comix.ws (2026-10-18).
